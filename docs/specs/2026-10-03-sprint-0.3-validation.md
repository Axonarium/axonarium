## Goal

Every file in `data/` is checked on every pull request, against the schema and against the rules the schema can't express. A pull request that deletes or retracts a claim can't merge without the maintainer's review. Sprint 0.2's review handed this sprint a list of gaps; all the offline ones are closed here.

## Decisions

| Decision | Choice |
| --- | --- |
| Deletion and retraction gate | A retractions log, `data/retractions.yaml`, owned by the maintainer through CODEOWNERS. Deleting a claim, or setting its status to `retracted`, needs a new log entry in the same pull request, so the pull request touches a maintainer-owned file and needs code-owner review. Recorded in ADR 0006 |
| Online checks | Out of scope: identifier and DOI resolution, retraction lookups, `data/sources/` filling and the excerpt-licence rule move to sprint 0.3b ([card #17](https://github.com/axonarium/axonarium/issues/17)) |
| Implementation | A Python package, `checks/`, at the repo root, run as `uv run python -m checks`. It uses LinkML's validator (one reused instance, JSON Schema plugin, closed classes) plus plain-Python rules. No new dependencies |

## Data layout

The folder decides the class; the file name must match the record's ID.

| Path | Class | File name |
| --- | --- | --- |
| `data/claims/**/` | ConnectivityClaim | `<id>.yaml`, such as `clm-pq22bk4dtz.yaml` |
| `data/homology/**/` | HomologyClaim | `<id>.yaml` |
| `data/entities/atlases/` | Atlas | `<id>.yaml` |
| `data/entities/regions/**/` | Region | the ID with `:` replaced by `_`, such as `MBA_295.yaml` |
| `data/entities/neuron_types/` | NeuronType | `<id>.yaml` |
| `data/sources/**/` | Source | not checked yet (sprint 0.3b sets the naming) |
| `data/retractions.yaml` | RetractionLog | fixed name |

Any other `.yaml` file under `data/` is an error (`unknown-location`). `data/README.md` is ignored. `data/allowlist.yaml` is reserved for sprint C.2 and ignored until then.

## Schema change (version 0.2.0)

- New class `RetractionLog` with `entries`: a list of `RetractionEntry`.
- New class `RetractionEntry`: `claim` (a `clm-` or `hom-` ID, required), `action` (`RetractionAction`: `deleted` or `retracted`, required), `reason` (required), `curation` (`Curation`, required).
- `data/retractions.yaml` is created with `entries: []`.
- A valid example `RetractionLog-example.yaml`; regenerated JSON Schemas (including `json/RetractionLog.schema.json`) and SQL; schema tests updated.

## Rules

Every finding prints as `<path>: <rule-id>: <message>`. Any finding makes the command exit with status 1.

**Per file**:

| Rule ID | Check |
| --- | --- |
| `yaml-error` | The file parses as YAML; the top level is a mapping |
| `duplicate-key` | No mapping repeats a key (YAML would silently keep the last) |
| `unknown-location` | The file is in a folder listed above |
| `schema` | LinkML validation against the folder's class |
| `file-name` | The file name matches the ID (rule in the layout table) |
| `extra-mapping` | `extra`, if present, is a mapping |
| `extra-key` | Every `extra` key matches `^[a-z][a-z0-9_]*\.[a-z0-9_.]+$` |
| `empty-text` | No string anywhere (outside `extra`) is empty or only whitespace |
| `non-finite` | No number anywhere is NaN or infinite |
| `uncertainty` | `sd` and `sem` are not negative; `ci_low` and `ci_high` come together and `ci_low` ≤ `ci_high` |
| `unit` | connection_probability, projection_density and fraction_of_labelled_neurons use unit `1` and lie in [0, 1]; synapse_count uses `1` and is ≥ 0; conduction_delay uses `ms` and is ≥ 0 |
| `absent-result` | A claim whose result is `absent` has no `strength`, no `measurements`, and sign `unknown` |
| `role` | In curation, a human's role is `curator`, an agent's is not `curator` or `verifier`; in verification, the role is `verifier` |
| `independent-verifier` | When an agent both curated and verified a claim, the two prompts differ |
| `doi-case` | DOIs (`source.doi`, and the `doi:` form of `Source.id`) are lowercase |
| `homology-pair` | A homology claim's two species differ, and its subject and object are the same kind of entity |
| `neuron-type-region` | A neuron type's `region` is a region |

**Across files**:

| Rule ID | Check |
| --- | --- |
| `duplicate-id` | No two records share an ID |
| `unknown-reference` | Every `nt-` ID and every atlas ID referenced has a record in `data/entities/` |
| `atlas-species` | A connectivity claim's species matches the species of every atlas its regions name; a homology claim's per-side species likewise |

**Changes in a pull request** (needs the base revision):

| Rule ID | Check |
| --- | --- |
| `deletion-unlogged` | Every deleted claim or homology file has a new log entry with action `deleted` for its ID |
| `retraction-unlogged` | Every claim whose status became `retracted` has a new log entry with action `retracted` |
| `log-rewritten` | Every entry in the base revision's log is still present, unchanged and in order |

## Commands

- `uv run python -m checks files [--data data]` runs the per-file and cross-file rules.
- `uv run python -m checks changes --base <git ref> [--data data]` runs the change rules against the base revision.

## Wiring

- A pre-commit hook, `data-checks`, runs `checks files` when anything under `data/`, `checks/` or the schema changes.
- The pytest hook runs `schema/tests` and `checks/tests`.
- In `.github/workflows/ci.yml`, the `checks` job checks out with full history and, on pull requests only, runs `checks changes` against the base branch. The base branch name reaches the shell through an environment variable, not inline `${{ }}`. Because `checks` is the required status, the gate cannot be bypassed.
- `.github/CODEOWNERS` names `@tjbanks` for `/data/retractions.yaml` explicitly, after the unowned data lines.

## Tests

- **Valid tree:** built when the tests run, by copying `schema/examples/valid/` into the data layout (each file under its class's folder with its file name rule), plus an empty retractions log. It must produce no findings, so the schema examples and the data rules can't drift apart.
- **Broken fixtures:** for every per-file and cross-file rule, a folder `checks/tests/fixtures/broken/<rule-id>/` holding only the files that differ from the valid tree, laid out as under `data/`. The test overlays it on a fresh copy of the valid tree, runs the `files` command, and expects findings with exactly that rule ID and no other.
- **Change rules:** each is tested in a temporary git repository with a base commit and a head commit, covering both the failing case and the logged, passing case.
- The command's exit status and output format are tested once.

## Verification

1. `uv run pytest -q schema/tests checks/tests` passes, with every broken fixture failing with its own rule ID.
2. `uvx pre-commit run --all-files` passes.
3. The change gate fails on a test pull request that deletes a claim without a log entry. This is covered by the change-rule tests; the CI step is exercised on this sprint's own pull request, which deletes nothing.
4. CI passes on the pull request.
