# Sprint 3.3a: Site shell on Vercel (design spec)

| | |
| --- | --- |

## Goal

Put the site on the internet now, on the plan's stack, so every later sprint (atlas meshes, Allen connectivity, the network and 3D views) lands on a live page. The data is still empty, so every page has a designed empty state.

## Decisions

| Decision | Choice |
| --- | --- |
| Scaffold | `create-next-app` (Next.js 16, App Router, TypeScript, Tailwind 4, ESLint) in `site/`, then `shadcn` init. The plan's `with-supabase` starter is the reference for the Supabase wiring only: its login pages, cookies and proxy are for accounts, which v1 doesn't have |
| Data access | `@supabase/supabase-js` with the publishable key, server-side only, in `site/lib/data.ts`. Pages revalidate every 5 minutes. If Supabase is unreachable or unconfigured, pages render with a "data unavailable" notice instead of failing |
| Deploy | `deploy.yml` job `site`, after `database`, in the `production` environment: `vercel pull`, `vercel build --prod`, `vercel deploy --prebuilt --prod` (Vercel CLI pinned), with `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID` and the two public Supabase variables. Never on pull requests |
| CI | A `site` job: `npm ci`, lint, typecheck, unit tests (Vitest), `next build` without Supabase variables |
| Region names | IDs only until sprint 1.2 brings atlas names at build time |

## Pages

| Route | Shows |
| --- | --- |
| `/` | Pitch, live counts (claims, edges, sources, species), how a claim becomes an edge, project status, links |
| `/explore` | Edges as a table, filterable by species and predicate (URL search parameters) |
| `/edges/[id]` | One edge: its counts and every claim behind it, with citations |
| `/claims/[id]` | One claim: subject, object, evidence, measurements, citation with source record (title, year, journal, licence, retracted), curation and verification |
| `/about` | What it is, licences, how to cite, how to contribute |

## Implementation notes

- **Scaffold:** `create-next-app@16.3.8` (TypeScript, Tailwind 4, ESLint, App Router, no `src/`), `shadcn@4.21.1 init`, and the shadcn/ui Button, Card, Badge and Table components (pages use them rather than hand-styled markup); `@types/node` 24 (Node 24 everywhere; Vitest 5 needs it). The generated `site/AGENTS.md` (Next.js's own agent rules: read `node_modules/next/dist/docs/` first) is kept.
- **Dark mode** follows the system (`prefers-color-scheme`), no theme dependency.
- **Edge URLs:** `/edges/<encodeURIComponent(id)>`; the page accepts the segment decoded or not.
- **Caching:** pages export `revalidate = 300`; `/explore` filters in the browser (`useSearchParams` under `Suspense`), so the page itself stays cached.
- **Unavailable data:** every query returns `{ok, data} | {ok: false, reason}`; pages render a notice. A build without the Supabase variables (pull-request CI) renders that notice instead of failing.
- **CI:** job `site` in `ci.yml`: setup-node 7.0.0 (pinned), `npm ci`, `npm run lint`, `npx next typegen && npx tsc --noEmit`, `npx vitest run`, `npm run build`. Added to the `main-ci` ruleset's required checks once it has run.
- **Deploy:** `deploy.yml` job `site` (`needs: database`, `environment: production`): `vercel pull`, `vercel build --prod`, `vercel deploy --prebuilt --prod`, Vercel CLI 62.2.0 via `npx`, with the public Supabase variables from repository variables.
- **Dependabot:** npm for `/site`, weekly, 7-day cooldown, like the other ecosystems.

## Tests

- Vitest: citation links (every identifier, DOI escaping), species and predicate labels, edge URL round trip.
- `next build` with and without Supabase variables; lint and typecheck in CI.
- Checked by hand before merge: the built site against the live (empty) Supabase serves `/`, `/explore` and `/about` with 200 and the empty states, and 404 for unknown edges, claims and paths.
