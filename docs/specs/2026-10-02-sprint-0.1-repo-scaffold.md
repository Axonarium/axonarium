## Goal

Turn the empty public repository [axonarium/axonarium](https://github.com/axonarium/axonarium) into a governed project that any human or agent can pick up cold. That means licences, community files, agent instructions, a sprint-card system, ownership rules, branch protection, and a CI workflow that passes on a repo with no code yet.

## Delivery sequence

1. **Bootstrap commit.** Push README.md (short version) and LICENSE straight to `main` while the repo has no rules. From this point a domain redirect to the repo shows something.
2. **Sprint card #1** for sprint 0.1, opened with gh.
3. **Scaffold pull request** from branch `sprint/0.1-scaffold`, holding every other file in this spec plus this spec and the implementation plan. Its description says `Closes #1`.
4. **CI passes** on the pull request. The maintainer reviews and squash-merges it, or tells Claude to.
5. **After the merge,** Claude applies the GitHub configuration, confirms the label sync ran, labels card #1, and opens the backlog cards.

### AGENTS.md outline

1. What Axonarium is, in two sentences, and a pointer to STATUS.md for the current phase.
2. Read first, in order: AGENTS.md, STATUS.md, your sprint card, the ADRs it links. docs/plan.md holds the full background.
3. The handoff protocol: the six steps from plan Part 1, "Agent operating model".
4. Merge rules: the plan's table, and how CODEOWNERS and the branch ruleset enforce them.
5. Roles: the plan's role table, condensed. Role prompts will live in agents/roles/.
6. Ground rules:
   - Adopt, don't invent. Check "Proven building blocks" in docs/plan.md first; a new dependency or a replacement needs an ADR and human review.
   - Agents never merge. Agents never merge or approve pull requests and never use the admin bypass, even through a maintainer's login; a human merges (plan principle 3).
   - Files are the truth. Agents never write to a database directly.
   - Provenance. Fill in the provenance fields of the pull request template.
   - Human-only paths. The gold set and evals, the allowlist, CODEOWNERS, licences and governance files change only when a sprint card says so, and always with human review.
   - CI safety. Never use `pull_request_target`, and never expose secrets to pull requests from forks.
   - Evidence. Store locators and paraphrases; verbatim excerpts only from openly licensed papers, kept short.
   - Never leave `main` failing CI.
7. Repository map: what exists now, and the planned directories from the plan's layout.
8. Before pushing: `uvx pre-commit run --all-files`.

## CI

One workflow, `.github/workflows/ci.yml`, named CI.

- **Triggers:** pull requests, and pushes to `main`. A new push to a pull request cancels its superseded run.
- **Token:** `contents: read` only, and no secrets. Triggered by `pull_request`, never `pull_request_target`.
- **One job, `checks`,** on Ubuntu with a 10-minute timeout. Its name is the required status check. Steps: check out without persisting credentials; install uv; restore the pre-commit cache keyed on `.pre-commit-config.yaml`; run `uvx pre-commit run --all-files --show-diff-on-failure` with a pinned pre-commit version.
- **Pinning:** every action is pinned to a full commit SHA, with its version in a comment. Dependabot keeps them current.

Hooks in `.pre-commit-config.yaml`, each pinned to a release:

| Source | Hooks | Catches |
| --- | --- | --- |
| [pre-commit/pre-commit-hooks](https://github.com/pre-commit/pre-commit-hooks) | check-added-large-files, check-case-conflict, check-merge-conflict, check-yaml, end-of-file-fixer, mixed-line-ending, trailing-whitespace (keeping Markdown hard line breaks) | Basic file hygiene |
| [python-jsonschema/check-jsonschema](https://github.com/python-jsonschema/check-jsonschema) | check-citation-file-format, check-dependabot, check-github-issue-forms, check-github-workflows-require-timeout | An invalid CITATION.cff, Dependabot config or issue form; a CI job without a time limit |
| [actionlint-py](https://github.com/Mateusz-Grzelinski/actionlint-py) | actionlint | Workflow syntax and expression errors |
| [zizmor](https://github.com/zizmorcore/zizmor-pre-commit) | zizmor | Workflow security problems: dangerous triggers, actions not pinned to a commit SHA (the default for all actions since zizmor v1.20), over-broad permissions, template injection, persisted credentials |
| [fsfe/reuse-tool](https://github.com/fsfe/reuse-tool) | reuse | A tracked file without declared licence and copyright |

The same command runs locally: `uvx pre-commit run --all-files`.

## GitHub configuration

Applied with gh after the scaffold pull request merges.

**Repository settings:**

- Squash merging only. The pull request title becomes the commit title and the pull request body the commit message, so provenance fields land in git history.
- Auto-merge allowed; branches deleted after merge; wiki off.
- Topics: neuroscience, neuroinformatics, connectome, connectivity, amygdala, knowledge-graph, linkml, sonata, open-science, mcp.

**Ruleset `main`,** active on the default branch:

- Pull request required, with 0 required approvals but review from code owners required. Stale approvals are dismissed when new commits are pushed. Squash is the only merge method.
- Status check `checks` must pass, from GitHub Actions. The branch need not be up to date before merging, so a stream of small agent pull requests doesn't force constant rebases.
- No force pushes, and no deletion.
- Bypass: organization admins, in pull-request mode only. They can merge a pull request that lacks the required review, but can't push to `main` directly. This is the plan's "admin bypass until a second maintainer joins".

## Verification

Sprint 0.1 is done when all of these hold:

1. `uvx pre-commit run --all-files` passes locally on the scaffold branch.
2. A sanity check, not committed, shows the hooks bite: a workflow job without `timeout-minutes`, and an action pinned to a tag instead of a SHA, each make the checks fail locally.
3. CI's `checks` job passes on the scaffold pull request, and again on `main` after the merge.
4. The labels workflow succeeds after the merge, and `gh label list` shows every label in labels.yml alongside GitHub's defaults.
5. `gh api repos/axonarium/axonarium/rules/branches/main` shows the ruleset's rules in effect.
6. `gh issue list --label sprint --state all` shows the 13 cards with the labels above, and card #1 is closed.
7. The repository settings read back as specified from `gh api repos/axonarium/axonarium`.
