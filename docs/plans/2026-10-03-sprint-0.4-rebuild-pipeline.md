# Sprint 0.4: Rebuild pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `uv run python -m build` validates `data/`, writes deterministic dumps, and loads Postgres in one transaction; CI proves it from an empty database, and pushes to `main` load Supabase.

**Architecture:** A `build/` package beside `checks/`. `build/tables.py` declares each table's columns and turns records into rows; `build/edges.py` aggregates claims; `build/dumps.py` writes files; `build/database.py` loads Postgres with psycopg; `build/cli.py` wires them. The checks' `run_files` and `load_tree` are reused.

**Tech Stack:** Python 3.13, psycopg 3.3.6 (binary), PyYAML, stdlib `csv`, `json`, `xml.etree`; pytest; Postgres 17 in CI, PGlite locally.

**Spec:** [docs/specs/2026-10-03-sprint-0.4-rebuild-pipeline.md](../specs/2026-10-03-sprint-0.4-rebuild-pipeline.md)

## Global Constraints

- Branch `sprint/0.4-rebuild-pipeline`; commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- "Run the tests": `uv run --frozen pytest -q schema/tests checks/tests build/tests` (database tests need `AXONARIUM_TEST_DATABASE_URL`; locally a PGlite server, in CI a Postgres service). "Run the checks": stage, then `uvx pre-commit@4.6.2 run --all-files`.
- Table and column names, edge rules, dump files and read-access rules exactly as in the spec.
- No SQL is built from data: identifiers come from the table declarations; values go through parameters.

## Review Focus

1. **A build against a database that already has unrelated tables** must leave them alone. Task 3 `test_other_tables_untouched`.
2. **An empty `data/`** (today's repo) builds: empty tables and dumps, exit 0. Task 4 `test_build_empty_data`.
3. **Text with characters that need escaping in SQL or CSV** (quotes, commas, newlines, non-ASCII) survives the round trip. Task 2 `test_csv_round_trip_awkward_text`, Task 3 `test_awkward_text_loads`.
4. **A failed database load** (for example a constraint violation half-way) rolls back to the previous data. Task 3 `test_failed_load_keeps_previous_data`.
5. **The database URL never appears in output**, including in error messages. Task 4 `test_database_url_not_printed`.
