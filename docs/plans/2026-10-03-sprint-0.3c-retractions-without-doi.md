# Sprint 0.3c: Retraction status for citations without a DOI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every citation a source record, keyed by DOI, else PubMed ID, else PMC ID, else arXiv ID, and make citations carry a DOI whenever PubMed knows one, so retracted papers are caught however they are cited.

**Architecture:** A pure `source_key` in `checks/identifiers.py` decides which record a citation needs; the offline rules and the online scope use it. `checks/sources.py` gains PubMed and PMC builders, and `fetch_source` takes a source ID of any scheme. `checks/online_rules.py` adds `citation-incomplete` and compares records of every scheme.

**Tech Stack:** Python 3.13, PyYAML, pytest, the sprint 0.3b fetcher and recordings. No new dependencies.

**Spec:** [docs/specs/2026-10-03-sprint-0.3c-retractions-without-doi.md](../specs/2026-10-03-sprint-0.3c-retractions-without-doi.md)

## Review Focus

1. **A claim citing both a PMID and a PMCID but no DOI**, where neither record names a DOI: the key is `pubmed:`, and no `citation-incomplete`. Task 3 `test_pmid_and_pmcid_without_doi`.
2. **arXiv citations with a version suffix** share one record: `2409.13740v2` keys to `arxiv:2409.13740`. Task 1 `test_source_key`.
3. **A PubMed `pubdate` without a usable year** (such as an empty string) leaves `year` out rather than crashing. Task 2 `test_pubmed_odd_pubdate`.
4. **Refreshing a mixed tree** (DOI, PubMed and arXiv records) rewrites only what changed. Task 2 `test_refresh_mixed_schemes`.
5. **`--base` scope for a changed PMID-only claim** includes its PubMed record. Task 3 `test_scope_includes_pubmed_record`.
