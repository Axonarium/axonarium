# Sprint 3.3a: Site shell on Vercel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `site/` serves the home, explore, edge, claim and about pages from the live Supabase tables, deployed to Vercel by GitHub Actions on every merge to `main`.

**Architecture:** Next.js 16 App Router with server components. `site/lib/data.ts` reads Supabase with the publishable key and returns `{ok, data} | {ok: false, reason}`; `site/lib/format.ts` holds pure helpers (tested with Vitest); pages revalidate every 5 minutes; the explore filters run in the browser.

**Tech Stack:** Next.js 16.3.8, React 19, Tailwind 4, shadcn/ui 4 (Base UI), `@supabase/supabase-js` 2.117, Vitest 5, Vercel CLI 62.2.0, Node 24.

**Spec:** [docs/specs/2026-10-03-sprint-3.3a-site-shell.md](../specs/2026-10-03-sprint-3.3a-site-shell.md)

## Review Focus

1. **Supabase unreachable or unconfigured** (pull-request CI, a paused free project): every page renders with the notice, never a 500. `npm run build` without variables.
2. **Edge IDs with `|` and `:`** survive the URL round trip. `lib/format.test.ts`.
3. **DOIs with characters that break URLs** are escaped in citation links. `lib/format.test.ts`.
4. **A retracted claim** shows the retraction note and no link to its (absent) edge. Checked by hand on the claim page.
5. **No secrets in the site:** only the two public variables; the deploy job alone holds the Vercel token, in the `production` environment.
