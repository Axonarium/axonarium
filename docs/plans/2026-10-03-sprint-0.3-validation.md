# Sprint 0.3: Validation CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Check every data file against the schema and the rules it can't express, and gate deletions and retractions behind the maintainer-owned retractions log.

**Architecture:** A `checks/` package at the repo root. `checks files` loads `data/`, validates each record with one reused LinkML validator, then applies per-file and cross-file rules. `checks changes --base <ref>` compares against a git revision. Pre-commit runs `checks files` and the tests; the CI job `checks` also runs `checks changes` on pull requests.

**Tech Stack:** Python 3.13, LinkML 1.11.1 (`linkml.validator`), PyYAML, git, pytest. No new dependencies.

**Spec:** [docs/specs/2026-10-03-sprint-0.3-validation.md](../specs/2026-10-03-sprint-0.3-validation.md)

## Global Constraints

- Branch `sprint/0.3-validation`; commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; never stage axonarium-project-plan.md.
- "Run the tests": `uv run --frozen pytest -q schema/tests checks/tests`. "Run the checks": stage, then `uvx pre-commit@4.6.2 run --all-files`.
- Rule IDs, the data layout, the file-name rules and the two commands are exactly as in the spec's tables.
- Output: one line per finding, `<path>: <rule-id>: <message>`, sorted by path then rule; exit status 1 if any finding, 0 otherwise.
- Validation uses a single `linkml.validator.Validator(SCHEMA, validation_plugins=[JsonschemaValidationPlugin(closed=True)])`, built once per run.
- YAML is loaded with a `yaml.SafeLoader` subclass that rejects duplicate keys.
- A file with a `yaml-error`, `duplicate-key` or `unknown-location` finding gets no further per-file rules. The `unit` rule skips values that `non-finite` reports.
- Schema version becomes `0.2.0`.

## Review Focus

1. **Real repo layout.** Files will sit in nested module folders (`data/claims/amygdala/...`). Task 2's test `test_nested_module_folders` puts a claim two folders deep and expects no findings.
2. **The change gate on a pull request with no data changes.** It must pass quietly. Task 5's test `test_changes_without_data_changes`.
3. **A base revision without `data/retractions.yaml`** (the first pull request after this sprint). Treat the base log as empty. Task 5's test `test_base_without_log`.
4. **Renaming a claim file** (git shows a delete plus an add) counts as a deletion unless the same ID still exists. Task 5's test `test_moved_claim_is_not_a_deletion`.
5. **Non-YAML files under `data/`** (README.md, editor files) are ignored, not reported. Task 2's test `test_ignores_non_yaml`.
