# Sprint 0.2: Schema v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A LinkML schema encoding the plan's data model, with generated JSON Schema and PostgreSQL DDL, and 20 example claims that validate.

**Architecture:** One schema file, `schema/axonarium.yaml`, is the single definition. Pytest checks it through LinkML's own validator: valid examples pass, invalid examples fail for the stated reason, generated files are current. Pre-commit runs the same tests through `uv`, so CI needs no workflow change.

**Tech Stack:** LinkML 1.11.1, Python 3.13, uv, pytest 9.1.1, pre-commit.

**Spec:** [docs/specs/2026-10-02-sprint-0.2-schema.md](../specs/2026-10-02-sprint-0.2-schema.md)

## Review Focus

1. **The generated JSON Schema outside LinkML.** Editors and other validators will use `axonarium.schema.json` directly. Task 5's test `test_json_schema_agrees_with_linkml` validates every example with the plain `jsonschema` library and expects the same verdicts as LinkML.
2. **Over-long excerpts.** `excerpt` is limited to 300 characters. Task 2's test `test_excerpt_limit` checks that 300 characters pass and 301 fail.
3. **Nested `extra` values.** Contributors will put lists and nested maps in `extra`. Example 1 carries a nested map and a list, and validates.
4. **Duplicate IDs across files.** Task 2's test `test_example_ids_are_unique` covers the examples; data files are sprint 0.3's job.
5. **Atlas prefixes the schema doesn't know yet**, such as a future rat atlas. Rule 2 rejects them, as intended until sprint 1.2 extends the pattern. schema/README.md says so; no test needed.
